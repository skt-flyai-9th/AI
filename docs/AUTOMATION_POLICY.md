# 자동화 운영 결정

## 현재 결정

트렌드 리서치와 데이터베이스 초기화는 서비스 최초 구성 시 한 번만 자동 실행한다.
완료된 랭킹 실행이 하나라도 존재하면 이후 배포의 initializer는 트렌드 리서치를 다시
실행하지 않는다. 사용자 제공 영상편집DB·상권분석DB 가져오기는 멱등하게 수행하며,
누락 또는 계약 복구가 필요한 버전만 생성한다.

현재 콘텐츠와 데이터베이스를 변경하는 자동 반복 실행은 모두 비활성화한다.

- 매일 트렌드 리서치: 비활성화
- 매일 분석 이력 정리: 비활성화
- 주간 DB 유지보수 후보 생성: 비활성화
- 편집 orphan 복구: 5분 간격 활성화

이력 정리와 DB 유지보수 태스크는 수동 운영을 위해 보존한다. 편집 orphan 복구는
콘텐츠 업데이트가 아니라 장애 복구 안전장치이므로 Celery Beat가 5분마다 실행한다.
`RUNNING` 상태가 설정된 stale 시간 이상 멈춘 작업만 대상으로 하며 복구 횟수도 제한한다.

## 추후 설계 항목

주기 업데이트를 다시 도입하기 전 다음을 별도로 결정한다.

- 업데이트 대상과 주기
- 새 트렌드의 자동 반영 또는 사람 승인 방식
- 기존 4개 영상의 교체·보존 정책
- 실패 재시도, 직전 정상 결과 유지, 알림 정책
- 상권분석DB·영상편집DB 후보의 검증·승인 책임자
- 분석 이력 보존 방식과 orphan 복구 운영 지표

이 문서는 “주기 업데이트 설계는 나중에 한다”는 현재 제품 결정을 저장하는 기준 문서다.
